# 🔔独自プッシュの実装計画(サーバーから端末への通知)

template-maui-server から端末へ通知を送る(FCM を使わない)。端末は前景サービスで SignalR の接続を保ち、受けた通知を邪魔にならない形(前面はトースト、背面はローカル通知)で出す。接続していない端末宛ての通知はサーバーが溜めておき、端末が接続したときに届ける。常時接続・再接続・前景サービス・ローカル通知の作りは `Works3/PushSample`(README に完結)を参考にする。番号は `Task_Checklist.md` の 3-1 と同じ。

| 番号 | 段階 | 内容 |
| --- | --- | --- |
| 3-1-1 | サーバー: 保存と配信 | 通知のテーブル(端末ごとの未達)、ハブ(端末 ID での接続、未達の送信、受け取りの応答)、送信の API |
| 3-1-2 | サーバー: 送信の画面 | ダッシュボードから端末 / 全端末へ送る、端末ごとの未達の件数 |
| 3-1-3 | 端末: 受信と表示 | 前景サービスの常時接続(設定画面のスイッチで始める、切れたら繋ぎ直す)、トーストとローカル通知、受け取りの応答 |

ファイルパスは、(server) が `template-maui-server/src/Template.MobileServer.Web/`、(core) が `template-maui-server/src/Template.MobileServer.Core/`、(app) が `Template.MobileApp/` からの相対。

## ⚖️決定事項

| 項目 | 決定 |
| --- | --- |
| 方式 | SignalR の接続でサーバーから送る(FCM は使わない。FCM は 3-2)|
| 端末での表示 | 邪魔にならない形。前面ではトースト、背面(常駐で受けたとき)ではローカル通知(受信用のチャンネル。音と振動なし)。操作を止めるダイアログは使わない |
| 未接続の端末 | サーバーが通知を溜めておき、端末が接続したときに届ける |
| ハブ | 通知専用の `PushHub`(`/hubs/push`)を足す(Network > Realtime の `MonitorHub` とは分ける)|
| 接続する期間 | PushSample と同じ前景サービス(`specialUse`、`START_STICKY`)で常時接続する。常駐の通知に接続の状態を出す(常駐の通知と電池の消費、電池の最適化からの除外が要る)|
| 宛先 | 端末ごと(登録済みの端末 ID)と全端末のどちらも選べる(全端末は送った時点の登録済みで有効な端末へ 1 件ずつ)|
| 溜める期間 | 7 日(オプション)。期限を過ぎた行は届いた / 届いていないにかかわらず消す |
| 常駐の開始と停止 | 設定画面(Main > Setting)のスイッチ。オンにすると常駐を始め、オンのままなら起動時に常駐を始める。オフで止める |
| 端末の画面 | 受信用の画面は作らない。接続の状態は常駐の通知に出す。電池の最適化の設定を開くボタンは設定画面のスイッチの近くに置く |

## 🗄️データ(`data.db`)

| 列 | 内容 |
| --- | --- |
| `Id` | 連番 |
| `DeviceId` | 宛先の端末 ID |
| `Title` / `Body` | 件名・本文 |
| `CreatedAt` | 送った日時 |
| `DeliveredAt` | 端末が受け取りを応答した日時(未達は NULL)|

- 全端末宛ては、送った時点の登録済みで有効な端末ごとに 1 行ずつ作る(端末ごとに届いたかを持つ)
- 期限を過ぎた行は保持期間の処理で消す

## 🔁配信の流れ

1. 送信(API / 画面)で行を作り、宛先の端末が接続中ならすぐにハブで送る
2. 端末は接続するときに端末 ID を渡す(`DeviceIdFormat` で確かめる)。ハブは接続を端末 ID のグループに入れ、未達の行を古い順に送る
3. 端末は表示した後に `Acknowledge(id)` を呼び、サーバーは `DeliveredAt` を記録する
4. 応答が無いまま切れた通知は、次の接続で送り直す(端末は同じ Id を 2 回出さない)

## 📱端末

| 項目 | 内容 |
| --- | --- |
| 接続 | 前景サービス(`Platforms/Android/PushService`)が `Services/PushConnection` の常時接続を持つ(`Mofucat.ReactiveHub` で繋ぎ直す。通信の状態が戻ったら繋ぎ直す)。接続先は API の接続先 |
| 常駐 | 設定画面のスイッチで始める / 止める(オンのままなら起動時に始める)。常駐の通知に接続の状態を出す。強制終了後は `START_STICKY` で再起動し、接続先は設定から読む。通知の実行時の許可(`POST_NOTIFICATIONS`)を求め、電池の最適化の設定を開くボタンを設定画面に置く |
| 表示 | 前面 = CommunityToolkit.Maui の `Toast`(件名と本文を短い 1 文にする)、背面 = ローカル通知(受信用のチャンネル。音と振動なし)|
| 応答 | 表示の後に `Acknowledge(id)`。表示済みの Id を覚えておき、送り直しで同じ通知を 2 回出さない |

## 🏗️構成

| ファイル | 役割 |
| --- | --- |
| (server) `Hubs/PushHub.cs` | 接続(端末 ID のグループ)、未達の送信、受け取りの応答 |
| (server) `Services/PushService.cs` | 送信(行の作成と接続中の端末への送信)、未達の照会 |
| (server) `Endpoints/PushEndpoints.cs` | 送信の API(`POST /api/push`。宛先の端末 ID(省略で全端末)、件名、本文)|
| (server) `Components/Pages/DashboardPage.razor(.cs)` + ダイアログ | 端末の行と全端末からの送信、端末ごとの未達の件数 |
| (server) `Workers/` の保持期間の処理 | 期限を過ぎた行の削除 |
| (core) `Accessors/PushAccessor.cs` + SQL / `Models/Entity/PushMessageEntity.cs` / (server) `Assets/Data/Schema.sql` | テーブルと SQL |
| (app) `Services/PushConnection.cs` / `MauiProgram.cs` | 接続と受信 |
| (app) `Platforms/Android/PushService.cs` + `AndroidManifest.xml` | 前景サービス(`specialUse`)と常駐の通知、サービスの宣言と権限 |
| (app) `State/Settings.cs` / `Modules/Main/SettingView.xaml` + `SettingViewModel.cs` | 常駐のスイッチ(設定に保存)と電池の最適化の設定を開くボタン |

## 🪜段階ごとの作業

### 🗄️3-1-1 サーバー: 保存と配信

テーブル、`PushService`、`PushHub`、送信の API、テスト。

確認: 接続中の端末に届く、未接続の間に送った通知が接続したときに届く、応答で届いた日時が入る。

### 🖥️3-1-2 サーバー: 送信の画面

ダッシュボードの端末の行と、全端末への送信(件名・本文を入れるダイアログ)。端末ごとの未達の件数を出す。

### 📱3-1-3 端末: 受信と表示

`PushConnection`、前景サービス、設定画面のスイッチ、トーストとローカル通知、応答。

確認: 前面で受けるとトースト、背面ではローカル通知が出る、常駐を止めている間に送った通知が接続したときに出る、同じ通知が 2 回出ない、スイッチをオンのまま再起動すると常駐が始まる。

## 🚫対象外

| 項目 | 内容 |
| --- | --- |
| iOS | 常駐の手段が無い(APNs が要る)|
| 認証 | 端末 ID をそのまま信じる(端末の登録の API と同じ)|
| 大量の端末 | スケールアウト(Redis のバックプレーンなど)は扱わない |
